# store-io v0.5.0 &mdash; macOS and the single-file container

**A macOS backend, and container format 2: a paged region table (65,536 regions by default), regions that grow, freed space reused, and a store that still opens when its region table is damaged, with three ways out. A store made by 0.4 or earlier opens read-only and is copied into format 2 with `store-io copy`.** `0.x` releases make no compatibility promise, the on-disk format included; see Upgrading.

```toml
[dependencies]
store-io = "0.5.0"
```

## What is new

**macOS** (APFS). `NativePlatform` is the POSIX backend there.
- Every flush is `F_FULLFSYNC`. At each writable create or open the volume is asked once whether it honours one; a volume that refuses makes the store Unsafe.
- Locks are open-file-description locks on macOS 14 and later, `flock` before. Space grows with `F_PREALLOCATE` and is released with `F_PUNCHHOLE`.
- The probe reads `fstatfs`, DiskArbitration and IOKit. A store on APFS on the Mac's own drive is meant to be flush-required; external, USB and Thunderbolt devices, disk images, removable media, RAID sets and anything not identified are Unverified; FAT, exFAT, FUSE and network volumes are Unsafe. Nothing on macOS is power-safe.
- **Not yet confirmed on a real Mac.** CI runs every suite on GitHub's macOS runners, which are virtual machines; the check on a Mac's own drive is scheduled for 0.6 or 0.7 (`docs/PLATFORMS.md` section 5).

**Container format 2**, the format 0.5 creates (`docs/FORMAT.md` Part I):
- A paged region table: 65,536 regions by default, each page committed on its own, so a provisioning rewrites one page, not the whole table.
- Regions that grow: in place within their capacity, and beyond it into new extents (`RegionOptions { size, max_size, validate }`, and store-wide defaults). A region is fixed-size by default; `max_size` caps one that grows. Freed space is reused.
- A damaged region is made unavailable without closing the store; the rest opens and works.
- One portable format: the same operations make the same container, field by field and byte for byte, on Linux, Windows and macOS, and each opens on every system (`tests/portable.rs`).

**A damaged region table opens, the damage reported and nothing guessed** (`docs/GUIDE.md` section 15). `MetadataReport::damaged_slots` names what was found. Three ways out:
- `Store::repair_unavailable(id)` releases an unavailable region's table entry: its bytes untouched, its name free again, its space free where no other region lies;
- `Store::accept_page_rollback(pages)` accepts stale table pages: each page's surviving copy becomes its only one, and whatever its lost commit held is given up;
- `copy_store` with `CopyOptions::accept_stale_pages` copies everything that can be copied into a new store, a stale page's regions in full, and reports what is past their recorded size.

**`copy_store` and `store-io copy`.** Copies a store into a new format-2 store: the way from format 1, and out of damage no repair can mend. A crash leaves no store under the target name, or the whole copy. 2-3x faster than its first version: the source's bytes are written once, read on a second thread while the fill writes.

**`StoreOptions::flushes_in_flight`** (1 to 4, default 1): flushes a store may have in flight at once.

## What changed in behaviour

- **Format 2 is the default.** A writable open of a format-1 store fails `Unsupported(FormatVersion)` after its flush-first step and before anything is written; `Store::open_readonly` and `store-io info` read it as before.
- **Durable writes are 1.4-1.8x faster with four or more writers where a flush is cheap**: a barrier that must wait gives its processor up, up to 32 times, before it sleeps. One writer is unchanged; a device whose flushes outlast the yields gains nothing and pays nothing measurable. It changes how a barrier waits, never when it is satisfied.
- A finished flush wakes only the barriers it covered, and waiting barriers sleep without the slot lock.
- A page write of one chunk within one run is one direct write on an idle queue (about 260 instructions fewer per durable write).
- A `Store::open` whose probe fails reports `DurabilityUnknown { op: Probe }` (was `Io`; create keeps `Io`).
- Creating a directory flushes its parent also when the directory already exists (an earlier attempt may have died before its flush).

## Fixed

- **`AppendRegion::resume_at` could mark unflushed bytes durable**: called after an append that was not yet durable, a later sync returned a receipt without flushing. It now moves the durable point only when everything appended in the open is already durable.
- **Two lost wakeups in the append frontier**: the last writer of a burst could wait forever.
- **A scan's visitor that called the store could deadlock**, and **an append waiting for room held a shared queue** that its own `Submitter`'s owner could need. Neither now waits while holding a shared queue.
- **Directory replaces from two handles could clobber each other**; a replace now holds the directory's lock. Object names that could resolve to another file (the directory's own, case-folded, with ignorable code points, Windows short names) are refused.
- **A device reached over a network was classed like a local drive** (NVMe over fabrics, iSCSI, NBD, RBD and others on Linux): it could be `FlushRequired`, or power-safe from the remote target's data. Storage Spaces disks, Identify Namespace answers for another namespace, the namespace atomic fields' valid bit (Windows) and null_blk (Linux) were also misclassed or misread.
- A release whose commit was durable could still fail; a release stopped deallocating at the first extent that failed; a panic between a `Submitter` append's reservation and its submission left a hole a barrier waited on; a `Submitter`'s durable writes could each get their own flush; the out-of-space and media-error checks used Linux's error numbers on macOS.

The full list is in `CHANGELOG.md`.

## How it was verified

- The full test suites on Linux, Windows and macOS, on stable and 1.85; clippy, rustdoc, Miri on the buffers, loom; the conformance suite on APFS (CI), NTFS, ext4 and XFS; the kernel matrix (5.15, 6.1, 6.6 in VMs); the dm-log-writes crash replay on ext4 and XFS; the fail-stop job; fuzz smoke; `cargo audit`, `deny` and `vet`.
- The simulator enumerates every crash point of every format-2 change, and every format-2 integrity guard has a mutation entry; the mutation run (825 entries) passes with no survivor.
- An idle store makes no system call, wakeup, timer or I/O for 60 s on every system: Linux on both tiers, macOS and Windows.
- **Performance gates**, on CI's memory-backed device with io_uring (the gate of record; Unverified class, relative to the raw primitive and fio on the same machine): every gate passes. G1, a lone 4 KiB durable write, is 0.46 µs over `pwritev2` + `fdatasync` against a 2 µs gate, in 20 alternated rounds, none over (0.4 could not resolve it); G3 is 95.9% of the raw primitive's rate; G6 (sequential 1 MiB writes) and G15 (8 durable writers 3.7x one), which 0.4.1 reported below their bars on the kernel-7.0 runners, pass.

## Upgrading

- Replace `0.4` with `0.5`. Most code compiles unchanged; these changes can need edits (each in `CHANGELOG.md`):
  - `StoreOptions::append_ring` (blocks) is now `append_window` (bytes, default 16 MiB): renamed so an old setting fails to compile instead of meaning something else.
  - `RegionId` is 64-bit (`from_raw(u64)`, `get() -> u64`).
  - `StoreOptions`, `CopyOptions` and `CopyReport` gain fields: build them with `..Default::default()`. `CopyReport` is no longer `Copy`.
  - `ReserveTag` is `#[non_exhaustive]`: a `match` on it needs a wildcard arm.
  - A `Directory` replace takes the directory's `.sio-lock` and fails `Locked`, without waiting, while another handle or process replaces there; the caller retries.
  - For implementers of `Platform`: `Platform::rename_noreplace`. For users of the flush domain: `barrier` takes the slot and the flush's number. In `store-io-format`: `slot::FORMAT_MAJOR` is now `FORMAT_1` and `FORMAT_2`.
- **A store made by 0.4 or earlier opens read-only.** Copy it into format 2 once: `store-io copy <from> <to>`, or `store_io::copy_store(from, to, CopyOptions::default())`. The copy is a new store; the original is not changed.
- A store made by 0.5 does not open with 0.4.
