# store-io 0.5.1

0.5.0 with the fixes from an independent review of it: no critical or high
finding, one medium and four low. The container format is unchanged; a
store made by 0.5.0 opens as before.

**One behaviour change, read before upgrading:** directory mode now has a
largest object size, 16 MiB by default. An object over 16 MiB that 0.5.0
wrote is refused `NotWritten(TooLarge)` by `read` until the handle is
opened with a larger limit (`Directory::with_max_object`); nothing is lost.
See Upgrading.

## Fixed

- **An open's memory is bounded by what the store can hold** (medium). A
  damaged or hostile container could claim up to 2^30 region-table pages,
  and an open read and kept one record per page, up to an allocation that
  aborted the process. A record claiming more pages than any store this
  version creates is now refused with `Unsupported(FormatVersion)` before
  a page is read.
- **Damage to the newest copy of a slot's header after a clean close is
  reported** in `MetadataReport::lost_header_writes`. The older value is
  still served, and the report says it may not be the newest written.
- **`Directory::read` no longer allocates a file's whole length
  unchecked.**
- **Windows: FAT and exFAT get past the attribute check**, so the probe
  can reach them and class them `Unsafe`, as documented. Tested by a unit
  test of the fallback; not yet run on a FAT or exFAT volume.
- **README** (wording only): a writable open writes the volume record and may heal one
  torn metadata write; only a read-only open, a scan and a lock acquisition
  change nothing.

## Upgrading

- **Directory mode has a largest object size**, 16 MiB by default
  (`Directory::DEFAULT_MAX_OBJECT`), changed per handle with
  `Directory::with_max_object`. A larger `replace` is refused
  `NotWritten(TooLarge)` before anything is written. An object over 16 MiB
  written by 0.5.0 needs a handle with a larger limit to read it.

## Versions to 1.0

0.6 adds several devices, background pacing, read streams and export and
